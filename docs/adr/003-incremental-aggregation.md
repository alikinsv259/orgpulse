# 003. Инкрементальный пересчёт агрегатов при live-патче

- Статус: принято
- Дата: 2026-09-16

## Контекст

Задание требует двух вещей одновременно: «агрегация считается один раз после загрузки данных
и мемоизируется» и «пересчёт агрегатов только для затронутого узла и его предков».

Наивная реализация — положить патч в кэш React Query и позволить `useMemo` пересобрать дерево
и агрегаты — формально работает, но нарушает второе требование: меняется идентичность `data`,
и полный `O(n)` пересчёт запускается на каждое событие.

## Решение

Патчи не пишутся в кэш React Query. Они копятся отдельным слоем состояния (`Map<id, patch>`,
схлопывание по `id`), а итоговый снапшот получается применением патчей к базовому:

```ts
const snapshot = useMemo(() => {
  let patched = baseSnapshot
  for (const patch of patchesById.values()) patched = applyOrgNodePatch(patched, patch)
  return patched
}, [baseSnapshot, patchesById])
```

`applyOrgNodePatch` считает три дельты (`headcount`, `budget`, `headcount × performance`),
поднимается от узла к корню по `parentId` и правит агрегаты только на этом пути — `O(глубины)`.
Полный обход не запускается.

Чтобы это стало возможным, в агрегат добавлено поле `weightedPerformance`. Из готового среднего
и новой численности исходную сумму произведений не восстановить, так что сумму приходится
хранить явно.

Патч с `updatedAt` не новее текущего — no-op, снапшот возвращается по той же ссылке.

## Альтернативы

- **Полный пересчёт на каждое событие.** Проще на десяток строк, но прямо нарушает требование.
  На 42 узлах разницы не видно — на тысячах видно будет.
- **Писать патч в кэш React Query.** Идиоматичнее для «кэш как хранилище сущностей», но тянет
  за собой полный пересчёт, см. выше.
- **Мутировать снапшот на месте.** Быстрее всего, но React не увидит изменений без ручного
  форсирования перерисовки.

## Последствия

- Кэш React Query отстаёт от отображаемого состояния между рефетчами. Расхождение сходится
  само: фоновый рефетч приносит свежие данные с сервера, а накопленные патчи после него
  становятся пустышками по `updatedAt`.
- Клонируется только ветка от узла до корня; остальные узлы переиспользуются по ссылке,
  поэтому React перерисовывает ровно затронутый путь.
- `Map` агрегатов копируется целиком на каждый патч — это поверхностное копирование `O(n)`,
  не пересчёт. На текущем размере данных незаметно; станет узким местом — понадобится
  персистентная структура.
- Корректность проверяется тестом: инкрементальный результат сверяется с полным пересчётом.
